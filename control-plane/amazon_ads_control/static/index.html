本页怎么理解

运行模式

自动运营：主控自动判断，Executor 只执行计划内操作，Verifier 独立读回。

仅观察：继续采集、分析和生成决策，但不修改广告。

暂停：阻断 Amazon Ads 读取、数据任务和写入，适合排查异常。

角色分工

Main 主控：采集数据、调用确定性策略、建任务和委派，不能写广告。

Executor 执行器：只能执行绑定任务中的单实体计划，不能自行扩展范围。

Verifier 验证器：只读重新查询 Amazon，不能修改广告，也不信任执行器自报结果。

判断原则

LLM 负责解释和编排；真正可执行的变化必须来自成熟数据和确定性规则。

数据过旧、归因未成熟、Schema 漂移或结果无法确认时，系统会停止写入并记录原因。

查看最近广告数据周期、主控创建的任务、Executor/Verifier 状态和系统运行记录。

最近周期

每一行代表一次广告数据快照和确定性策略计算；“决策”是本周期产生的候选动作数量。

任务与 Worker

任务由 Main 创建；Executor 执行计划，Verifier 在不同会话中独立读回。Worker 角色由系统自动识别，不能在 Web 中手动冒充。

系统事件

记录模式变化、任务生命周期、工具阻断、数据质量和安全事件，用于解释系统为何执行或停止。

这里展示策略引擎基于实际广告数据生成的计划。决策不等于已经执行，只有满足全部安全条件后才会被 Executor 领取。

确定性策略决策

“原因”说明命中的规则与证据；“计划”保存实体、修改前后值、预期状态和匹配字段。

先看 Executor 的真实工具调用和结构化返回，再看独立 Verifier 是否从 Amazon 读到了预期状态。

工具调用与结构化结果

记录调用前授权、调用后结果、允许或阻断原因。部分成功、异步处理中和未知响应不会被误记为已完成。

独立 Verifier 读回

Verifier 必须是不同的只读子代理；只有实际状态与计划一致，决策才会标记为 verified。

异常不会自动消失。先处理关键异常，再恢复自动运营；严重异常会让写入 fail-closed。

需要关注

包括 MCP Schema 漂移、工具消失、预算接近耗尽、广告失去资格、执行结果未确认和验证不一致。

管理广告 Profile 的核心目标，并查看 Hermes 当前真实发现的 Amazon Ads MCP 工具合同。

广告 Profiles

每个 Profile 对应一个广告账户/市场。策略可按 Profile 覆盖全局默认值。

核心策略

这些是运营边界，不是一次性操作按钮。保存后用于后续新决策；已经执行的历史不会被改写。
